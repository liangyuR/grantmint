# 单设备激活与长期离线授权

管理端默认使用中文，创建授权默认选择 v2 单设备离线模式。v1 模式保留用于兼容现有客户端；两种模式不能在已签发授权上直接互换。

本页描述当前 Java 后端与 Rust 校验器的已实现行为。后续服务端采用 [Rust 精简方案](../architecture/offline-device-licensing.md)，移除策略引擎和 v1 新签发；切换前仍按本页操作，不代表 Rust 后端已上线。

## 使用规则

- 一个产品对应一个软件。每份 v2 授权绑定一组设备公钥和版本化指纹，只允许一台设备。
- 创建授权时确定合同停用时刻，必须选择有限的未来日期。v2 授权固定为单席位、零宽限；所选策略提供权益快照，其 v1 席位数、宽限期和心跳参数不会改变 v2 规则。
- 创建成功只返回待激活授权和一次性展示的激活秘密，不返回可运行证书。妥善交付激活信息；它不是可公开展示的授权编号。
- 设备首次激活需要联网，服务端校验设备私钥持有证明后才签发 v2 证书。已激活设备在 exp 前可完全离线使用，无心跳和周期联网要求。
- 将证书复制到另一设备，若设备密钥或当前指纹不匹配，Rust 校验器拒绝。应用必须从本机设备适配器取得实际指纹，不能把证书中的指纹当成当前设备输入。
- 到期边界是 `now >= exp`；没有宽限期。北京时间日期表示当天 00:00 停用，不是当天结束。
- 暂停或撤销能阻止服务端继续办理请求，但已下载、未到期的离线证书不会被远程即时禁用。管理员不能通过旧版解绑接口给 v2 更换设备。

此阶段交付服务端协议、管理界面与 Rust 校验库/CLI。续期重签、换机审批、完整的可信时间在线恢复，以及 GlueSight 的硬件指纹采集、系统保护存储和工件入口接入需要后续实现。不要把示例 CLI 当成已完成防破解的生产客户端。

## 设备与应用信任边界

应用预置不可变产品 UUID、可信签名公钥和签名 key ID，不从未认证的服务器响应或证书自行建立信任。设备生成自己的 Ed25519 密钥；服务端只获得原始 32 字节公钥，不接收设备私钥。

设备指纹由客户端按版本化算法计算，协议传递 SHA-256 摘要而不上传原始硬件标识。本次库校验摘要与版本的一致性；不同产品/平台的稳定标识采集由集成方提供并测试。复制整个系统和密钥、修改客户端、回滚完整虚拟机快照仍超出普通软件方案的可靠防护范围。

Windows 生产集成应使用 DPAPI 与文件 ACL 保护私钥和时间状态；Linux 使用系统凭据存储或受限文件。状态应与产品、授权和设备身份绑定，原子持久化最高时间与证书版本。未初始化、丢失、损坏的状态不可在离线运行时静默重建为新激活。

## 验证与运行

### 激活 API

所有公网请求应通过 HTTPS。管理端创建接口沿用管理员认证与 CSRF 防护；设备接口通过激活秘密和设备私钥证明认证。

| 接口 | 请求字段 | 返回 |
| --- | --- | --- |
| `POST /admin/v2/licenses` | `productId`、`policyId`、`holder: {name,email}`、带时区的 `expiresAt` | `licenseId`、`keyId`、仅创建时返回的 `activationSecret`，无证书 |
| `POST /v2/licenses/challenges` | `productId`、`licenseId`、`activationSecret`、`devicePublicKey`、`fingerprintHash`、`fingerprintVersion: 1` | `challengeId`、`nonce`、`message`、`expiresAt` |
| `POST /v2/licenses/activate` | `productId`、`licenseId`、`challengeId`、`signature`、`idempotencyKey` | `token`、`timeReceipt`、`serverTime`、`revision`、`bindingVersion`、授权标识 |

设备公钥是原始 32 字节的标准 Base64；指纹摘要、挑战消息和签名使用无填充 base64url。客户端必须核对挑战中的产品、授权、公钥和指纹，再对解码后的 `message` 字节签名。幂等键为 16–128 位字母、数字、下划线或连字符，每次新激活操作独立生成。

挑战有效期为五分钟。相同挑战、签名和幂等键重试返回原响应；已消费挑战保留至少 24 小时后由定时清理删除。客户端首次接受时间回执仍要求处于挑战有效窗口，超过窗口应由同一设备申请新挑战，取得同一证书和新的时间回执；不能借重放旧回执重置本地时间高水位。另一设备或变化的指纹返回 `device_already_bound`，不会替换已有绑定。

服务端按可信代理解析后的客户端地址限制激活请求，并限制每份授权的挑战记录数量。尚未激活但已过期的记录仍显示待激活，激活接口会立即拒绝；已激活授权的后台状态刷新不影响客户端按证书期限准时停用。

Rust SDK 的运行说明见 [verifiers/rust](../../verifiers/rust/README.md)。离线校验必须同时检查签名、产品、协议版本、设备密钥持有、指纹、有效期及本地防回退状态。业务层在接收每个新任务时调用校验，并在启动、唤醒和运行过程中重新计算期限。

库的提前七天状态用于前端提醒；GlueSight 应在到期后拒绝新工件，允许当前工件安全结束，保留查询、导出和激活/后续续期入口。本仓库不修改 PLC 协议或机器人控制逻辑。
