# 单设备激活、长期离线与续期

当前后台为 Rust 服务和普通中文 React Web 页面，不需要安装 Tauri 管理客户端。页面只保留应用、授权和审计，所有新授权均为 v2 单设备离线模式。

## 操作流程

1. 部署人员为每个应用生成独立签名密钥，在密钥配置文件登记公钥并重启服务。
2. 管理员在浏览器选择已部署公钥创建应用；应用 UUID 和标识不可修改。
3. 创建授权时填写客户、未来停用日期和可选权益，无需建立策略。权益允许布尔、文本和安全范围整数，默认空对象。
4. 创建成功仅本次显示激活秘密。关闭后不能重新查看；授权记录尚无可运行证书。
5. 客户设备持激活秘密、公钥及实际硬件指纹申请挑战，证明持有设备私钥后领取绑定证书。
6. 激活后至合同 exp 均可完全离线运行，不要求心跳或周期联网；确认不是心跳，不影响正常离线使用。

每份授权固定一台设备，无宽限期。停用日期使用北京时间当天 00:00，到期边界 `now >= exp`；例如 2026-12-01 表示 12 月 1 日零点停用，提前七天提醒从 11 月 24 日零点开始。

## 续期和交付状态

管理员在授权详情输入严格晚于旧期限的新停用日期和原因。服务端检查 expectedRevision，保持应用和设备身份不变，只递增合同 revision 并重签。重复相同幂等请求不会重复延长；并发冲突要求刷新后重新确认。

- **待激活**：还没有绑定设备，也没有运行证书。
- **待领取 / 尚未确认**：证书已签发，客户端尚未确认已验证并保存；不能据此推断客户已经使用新期限。
- **设备已确认**：设备完成独立 ack 挑战，确认对应 serial 已保存。

客户主动联网同步后，SDK 校验本次签名时间回执、产品、授权、设备、期限和不回退的版本，将 token 与保护状态原子替换，再确认 serial。旧证书过期仍可进入同步入口。若一直不联网领取，到旧 exp 仍然停用；服务端不能把新期限自动传到离线设备。

## 撤销、归档和恢复

撤销阻止后续激活、同步和续期，但不能即时禁用已经下载的未到期离线证书。页面会明确提示这一限制。归档应用阻止新授权和续期，不剥夺既有合同的激活/同步；应用与授权不硬删除。

不提供自由解绑、自助换机、暂停/恢复、v1 新签发、心跳或浮动席位。换机审批、遗失激活秘密补发、保护状态/可信时间恢复尚未实现，异常时不能自动重建状态放行。

## 激活 API

管理会话采用 HttpOnly Cookie 和 CSRF；设备通过激活凭据与私钥证明认证。首次激活保持 Java v2 字段和消息字节兼容：

- `POST /v2/licenses/challenges`：productId、licenseId、activationSecret、devicePublicKey、fingerprintHash、fingerprintVersion=1。
- `POST /v2/licenses/activate`：productId、licenseId、challengeId、signature、idempotencyKey。

挑战有效期五分钟，message 为需核对后签名的 base64url 字节。设备公钥为标准 Base64 原始 32 字节；指纹摘要和签名为无填充 base64url。服务端事务内锁定授权，校验设备与期限后才绑定签发；第二设备返回冲突。

相同挑战、签名和幂等键在保留期内可取回原响应。客户端接受时间回执仍要求本次挑战窗口有效，超过窗口需原设备重新申请挑战；不能重放旧回执重置时间状态。限流及挑战容量有上限。

完整管理、同步、确认及错误契约见 [Rust 服务 API](../api/rust-service.md)。

## 客户端边界

应用预置产品 UUID 和可信公钥集合，不从待验响应自行建立信任。硬件指纹必须由本机重新采集，不能抄证书里的摘要。实际设备私钥持有证明、签名、产品/设备/指纹、时间与版本高水位均通过后，业务还必须判断 `allows_new_work()`。

[SDK/CLI](../../verifiers/rust/README.md) 已实现离线验证和续期证书接受。CLI 的文件为演示存储；GlueSight 的硬件指纹采集、Windows DPAPI/ACL、Linux 保护存储、提醒展示及工件入口接入在其自身仓库完成。到期应禁止新工件并允许当前工件安全结束，本仓库不修改 PLC 协议。

纯软件无法保证防御管理员改客户端、克隆整机和快照回滚。新增保护状态包含 serial，旧开发版状态不可静默重建；真实旧状态需按迁移说明独立核验。
