# Java v2 → Rust 数据迁移

`import-v2` 随 Rust 镜像和二进制发布，只读源库，目标必须为已完成 SQLx 迁移的独立空业务库。它不修改旧 Flyway 数据库，不迁移管理员密码/会话，也不拷贝私钥。

## 前置条件

- 备份源库、私钥和 key ID 映射，冻结源、目标业务写入。已下载证书仍可离线使用。
- 目标先运行 `grantmint-server migrate`。已有管理员不妨碍迁移，但任何应用、授权、证书或审计业务记录都会使工具拒绝导入。
- v1、SUSPENDED、无法表示的状态和人工提前标记过期的记录均拒绝导入，不能自动改为有效。可用 `IMPORT_PRODUCT_ID` 选择一个应用，同应用混有 v1 时仍拒绝。
- 等待未消费挑战五分钟和已消费挑战的 24 小时幂等保留期结束，不丢弃仍承诺可重试的响应。
- 独立把签名私钥迁入新密钥卷。旧 Java hex 文件需安全转换为原始 32 字节 seed，核对同一 key ID 公钥一致，不能生成替代密钥。

## 执行

通过受保护环境配置设置 `SOURCE_DATABASE_URL`、`DATABASE_URL`，分别指向源 Java 库和目标 Rust 库；按需设置 `IMPORT_PRODUCT_ID`。不要在命令参数或源码中写入口令。

```sh
import-v2
```

默认只检查：使用重复读、只读源事务，验证产品/密钥关系、原证书签名、设备/期限/修订一致性。只输出数量，不输出客户资料、证书或秘密。空目标检查短暂锁定业务表，应在迁移窗口运行。

确认两端写入已冻结后：

```sh
import-v2 --apply --writes-frozen
```

`--writes-frozen` 是操作人员的停写声明，不会自动关闭源服务。应用时再次验证，目标事务持有业务表锁并重查空库，全部提交或全部回滚。重复执行不会覆盖已有业务数据。

保留应用/授权 UUID、展示编号、客户、期限、权益快照、激活秘密摘要、绑定、revision/binding_version、serial、原 token 字节、签名 key ID、撤销时间/原因及相关审计。旧证书不重签。

## 验收与回滚

核对记录数量与证书摘要，用原公钥验证原证书，再验证授权列表、新激活、原设备同步和续期。部署公钥必须匹配导入数据库，缺少当前私钥时不允许签发。

工具不迁移客户端保护状态。新 SDK 状态包含必填 serial，旧开发版缺少时拒绝加载；真实旧状态需另行核验原证书和受保护状态后迁移，不能从待验新证书猜测可信高水位。

新服务首次写入前可保留旧服务恢复路径；产生新绑定或修订后，不能直接恢复旧库回滚，须冻结写入并核对增量。不要删除原库或密钥备份来完成切换。
